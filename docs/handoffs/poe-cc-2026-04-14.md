## Architecture Notes

- **Backward Compatibility**: All new Message fields are optional. Old clients that don't populate mentions/directedTo still work; decision flow defaults to ignore.
- **Memory Efficiency**: Reactions stored in RoomStateManager (in-memory), not persisted to hub DB. On checkout, filtered reactions are included in memory fragment for agent's record.
- **Token Savings**: ConversationEvent (~200 bytes) sent instead of full Message (~2KB) to agents who don't respond. Estimated 60-70% token reduction in multi-agent rooms.
- **Rule-Based Decisions**: No LLM calls. v0.4 can upgrade to lightweight LLM decision calls if needed.
- **Bartender Reactions**: Runtime can synthesize reactions even if bartender agent doesn't implement SDK (emoji selected by context heuristic). Backward compatible.
